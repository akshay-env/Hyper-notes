## Context

HyperLink Notes v2.0.1 (SolidJS + Tauri v2, Rust backend) is feature-complete but six
behaviours are wrong or missing. All six were reported from real use of the **desktop
build**, not the browser preview:

| # | Reported problem | Root cause (verified in source) |
|---|---|---|
| 1 | Asking the AI in a freshly-opened note puts the conversation at the **top**, and the view doesn't follow it | `state/ai.ts:90` anchors to the **cursor line**; a just-loaded note has the caret at offset 0 |
| 2 | App starts on an **empty vault** with no way in; the previous vault isn't remembered | No vault-gate screen exists at all, and `vaultRoot` is never persisted |
| 3 | Selecting several notes and deleting bins **only one** | Two provable races: concurrent `.bin/index.json` writes, and `flushEditor()` re-creating a note file after it was moved to the bin |
| 4 | The find-in-note bar never collapses on an outside click | `NoteSearchBar.tsx` has no outside-click handler (only Esc) |
| 5 | The selection right-click menu has the wrong actions | Current menu is Ask AI / Bold / Italic / Highlight / Create note / Extract / Copy |
| 6 | No keyboard shortcut for "Ask AI about this" | Only `Ctrl+K` exists, and it toggles the whole-note Ask bar |

**Intended outcome:** a desktop app that opens into the vault you last used (or a clear
landing screen), reliably bins everything you selected, drops AI conversations at the end
of the note and scrolls to them, collapses the find bar like every other transient
control, and offers a text-editor-shaped right-click menu with coloured highlights and a
keyboard shortcut for Ask AI.

### Decisions already made with you

1. **AI anchor** — a whole-note ask always appends at the **end of the note**; a
   selection-scoped ask still lands just below the highlighted passage.
2. **Menu scope** — the selection menu becomes **exactly** the 8 requested items. Bold,
   Italic, `Create note "X"` and `Extract to new note` are **removed**.
3. **Highlight syntax** — default swatch keeps `==text==`; coloured swatches write
   `<mark style="background:#RRGGBB">text</mark>` (portable to Obsidian/GitHub).
4. **Paste** — add `tauri-plugin-clipboard-manager` for a reliable desktop clipboard.

### Constraint that shapes the plan

Memory `releases-must-build-in-ci`: **local Tauri builds are blocked by Smart App
Control.** Every fix here is therefore designed to be *frontend-only* except Fix 5's
clipboard plugin. Fixes 1–4 and 6 are verifiable with `npm run dev` alone. The single
Rust change (Fix 5) is isolated to three lines + one capability entry so it can be proven
in one CI tag build if `npm run tauri dev` won't run locally.

## Fix 1 — AI conversation appends at the end of the note, and scrolls there

**File:** `src/state/ai.ts` (only)

### Current code (lines 88–99)

```ts
const insertPos = sel ? Math.min(sel.to, view.state.doc.length) : view.state.selection.main.head;
const line = view.state.doc.lineAt(insertPos);
const anchor = line.to;
const lead = line.text.trim() === "" ? "" : "\n";
const block = `${lead}\n> ${q}\n\n`;
view.dispatch({ changes: { from: anchor, insert: block }, selection: { anchor: anchor + block.length } });
```

### Change

1. `insertPos` for a **whole-note** ask becomes `view.state.doc.length` instead of
   `view.state.selection.main.head`. The `sel` branch is untouched.
2. Tidy the separator so an empty note doesn't start with a blank line:
   ```ts
   const doc = view.state.doc;
   const insertPos = sel ? Math.min(sel.to, doc.length) : doc.length;
   const line = doc.lineAt(insertPos);
   const anchor = line.to;
   const lead = anchor === 0 ? "" : line.text.trim() === "" ? "\n" : "\n\n";
   const block = `${lead}> ${q}\n\n`;
   ```
   (Same output as today for every non-empty case; only the empty-document case improves.)
3. Add an explicit scroll to the dispatch:
   ```ts
   import { EditorView } from "@codemirror/view";   // new import
   …
   view.dispatch({
     changes: { from: anchor, insert: block },
     selection: { anchor: anchor + block.length },
     effects: EditorView.scrollIntoView(anchor + block.length, { y: "center" }),
   });
   ```

### Why this cannot regress anything

- `Typewriter` is constructed with `anchor + block.length` — the same expression, just a
  different anchor. Streaming, Stop, the note-switch guard and the trailing newline
  (`typer.pos`) all key off that value and need no change.
- Streaming already scrolls (`ai/typewriter.ts:145` sets `scrollIntoView: true` on every
  chunk); this only adds the **initial** jump, which was the missing half.
- Selection-scoped asks keep `Math.min(sel.to, doc.length)` — the "answer next to the
  passage" placement you get from right-click → Ask AI is preserved.
- `flushEditor()` on completion/error is unchanged.

## Fix 3 — Deleting a multi-selection bins everything selected

I traced this to **two independent races**, both provable from the source. Both are fixed;
the first thing to do at implementation time is reproduce and record which one you were
seeing (see Verification).

### Bug D1 — concurrent `.bin/index.json` writers (last write wins)

`state/ui.ts:425` loops `for (const p of tops) moveToBin(p)`. Each `moveToBin`
(`state/bin.ts:76`) fires `moveToBinFs(root, path, id)` **without awaiting**. Tauri commands
are plain `fn`s dispatched to the blocking pool, so N of them run concurrently. Rust
`move_to_bin` (`src-tauri/src/commands/bin.rs:98-100`) does an unlocked read-modify-write:

```rust
let mut idx = read_index(&dir);   // all N read the SAME old index
idx.insert(0, entry.clone());
write_index(&dir, &idx)?;         // last writer wins → index lists ONE entry
```

The files are all moved into `.bin/`, but the index records one. After a restart the Bin
shows a single item and the rest are orphaned and unrecoverable through the UI.

### Bug D2 — `flushEditor()` re-creates a note *after* it was binned

`confirmDelete` (`state/ui.ts:418`) calls `flushEditor()`, which fires
`writeNoteFs(root, loadedPath, text)` un-awaited (`state/editor.ts:46`). Rust `write_note`
does `create_dir_all(parent)` + `fs::write`. If that write lands **after** `move_to_bin`
renamed the file away, the note is **re-created at its original path**. It's gone from the
UI but back on disk, and it reappears on the next vault open — so when you delete two
notes and one of them is the note open in the editor, that one comes back.

### Bug D3 (same class, found while reviewing) — rename can leave a duplicate file

`renamePath` (`state/ui.ts:339`) also calls `flushEditor()` and then fires
`renamePathFs(...)`. If the write lands after the rename, the note is re-created at its
**old** path and the vault ends up with both. The existing comment at `ui.ts:354-356`
already worries about ordering between the rename and the link rewrites — but hope, not a
mechanism, is what currently orders them.

### The fix — one FIFO queue for every vault-mutating invoke

**3a. `src/backend/vaultApi.ts` — a single write queue (the whole fix, ~10 lines)**

All three bugs are the same bug: **un-awaited Tauri invokes that read-modify-write the
same files, dispatched concurrently onto Rust's blocking pool.** Fix it once, at the
boundary, instead of three times at the call sites:

```ts
// Every mutating command below read-modify-writes vault files (index.json, a note,
// a path). Tauri runs commands concurrently on the blocking pool, so two in flight
// at once lose each other's work. One FIFO chain = one writer at a time; reads stay
// unqueued. `then(fn, fn)` keeps a failed op from stalling the chain.
let writeChain: Promise<unknown> = Promise.resolve();
function enqueue<T>(fn: () => Promise<T>): Promise<T> {
  const next = writeChain.then(fn, fn);
  writeChain = next.catch(() => {});
  return next;
}
```

Wrap the **mutating** exports only (lines 33-48): `writeNoteFs`, `createFolderFs`,
`createNoteFs`, `renamePathFs`, `moveToBinFs`, `restoreBinFs`, `deleteBinFs`, `emptyBinFs`.
Leave the reads (`readVaultFs`, `readFileFs`, `listBinFs`) alone.

**Why this shape and not per-call-site awaits:**

| | Global queue | Per-site `await` |
|---|---|---|
| Call sites changed | **zero** | `bin.ts`, `ui.ts`, `editor.ts`, `DeleteConfirmDialog.tsx`, `TitleBar.tsx` |
| Signatures changed | **none** | `flushEditor` and `confirmDelete` become async, rippling outward |
| Fixes D1 (bin index) | ✅ | ✅ |
| Fixes D2 (flush after bin) | ✅ | ✅ |
| Fixes D3 (rename duplicate) | ✅ | ❌ still open |
| Orders link-rewrite writes after the rename (`ui.ts:354`) | ✅ guaranteed | ❌ still hoped-for |

`flushEditor()` stays synchronous, `confirmDelete()` stays synchronous, `moveToBin()` stays
synchronous — every store mutation still lands in one frame, so the tree updates for all
selected items at once. Only the disk side is serialised.

**3b. Harden the selection snapshot — `src/components/sidebar/FileTree.tsx`**

`ContextMenu.multi()` (line 265) reads `treeSelection()` at *select* time, several
interactions after the menu opened. Capture it at open time instead:

```ts
interface CtxMenu { x: number; y: number; node: VaultNode; paths: string[] }
```
`onContextMenu` (line 147) stores `paths: [...treeSelection()]` after its existing
retarget; `multi()` reads `held()!.paths`. Pure hardening — it removes any dependence on
what happens to the selection between right-click and click.

**3c. Cosmetic** — `loadBinEntries` (`state/bin.ts:129`) hardcodes `itemCount: 1`, so a
restored-from-disk folder always reads "1 item". Low priority; fix only if trivial.

### Regression review

- **Order is preserved**, and is now the order the code always intended: FIFO submission.
- **No deadlock or stall risk.** Every mutating call in the app is fire-and-forget except
  `restoreBinFs`, whose `.then()` still receives its own result. Nothing awaits one of
  these on a UI-blocking path, and `then(fn, fn)` means a rejected op still advances the
  chain.
- **No flooding.** There is no per-keystroke autosave — `flushEditor` runs on tab swap,
  rename, delete, window close and after an AI answer. The queue depth stays tiny.
- **Browser build unaffected**: `vaultRoot()` is null, so none of these are called at all.
- **`restoreFromBin`'s optimistic `setBinItems(...)`** stays synchronous; the panel still
  updates instantly.

## Fix 4 — Find bar collapses on an outside click

**Files:** `src/components/editor/NoteSearchBar.tsx`, `src/components/editor/EditorToolbar.tsx`

Mirror the pattern `AskBar.tsx:72-83` already uses (capture-phase `mousedown` on
`document`, so it beats CodeMirror's own handling):

```tsx
let rootRef: HTMLDivElement | undefined;

const onDocDown = (e: MouseEvent) => {
  if (!noteSearchOpen()) return;
  const t = e.target as Element | null;
  if (rootRef && t && rootRef.contains(t)) return;        // the bar itself, field, ▲ ▼
  if (t?.closest?.("[data-find-toggle]")) return;         // let the toolbar button toggle
  setNoteSearchOpen(false);
};
onMount(() => document.addEventListener("mousedown", onDocDown, true));
onCleanup(() => document.removeEventListener("mousedown", onDocDown, true));
```

`EditorToolbar.tsx:65-71` gains `data-find-toggle` on the Find button. Without that guard
the sequence would be *mousedown closes → click re-opens*, and the button would appear
dead.

### Regression review

- The component is permanently mounted (`App.tsx:69-71` only toggles a class on the slot),
  so `onMount`/`onCleanup` run exactly once. No listener leak.
- Closing already clears the query and the highlights via the existing `createEffect`
  (`NoteSearchBar.tsx:23-34`) — nothing new needed.
- `.note-search-slot` is `pointer-events: none` while closed (`chrome.css:497-514`), so a
  click "through" it hits the editor as before.
- Esc-to-close (line 61) is untouched.
- Clicking into the document now closes the bar. That is the requested behaviour; call it
  out when you demo it.

**New module `src/editor/highlight.ts`** — one place that owns the syntax:

```ts

  { id: "yellow", label: "Yellow", hex: "#ffd54a" },
```

  - no hit → wrap the trimmed selection in the chosen form;
  - hit with the **same** colour → unwrap (remove the markers, keep the text);
  - hit with a **different** colour → re-wrap the existing inner text in the new form.

**Live-preview rendering — `src/editor/livePreview.ts`, inside `scanInline` (line 671)**

Add a `run()` rule immediately **before** the existing `==` rule at line 716 (so the
`consumed` tracker gives `<mark>` priority and the two can't overlap):

```ts
run(/<mark(?:\s+style="[^"]*")?>([\s\S]*?)<\/mark>/g, (m, s, e) => {
  if (active(base + s, base + e)) return;              // caret on it → show raw markdown
  const raw = /background:\s*(#[0-9a-fA-F]{3,8})/.exec(m[0])?.[1];
  const hex = raw && isHex(raw) ? raw : null;          // theme/colorEngine.isHex
  const openLen = m[0].length - m[1].length - 7;       // "</mark>".length
  hide(base + s, base + s + openLen);
  mark(base + s + openLen, base + e - 7, "cm-highlight",
       hex ? { style: `background-color:${hex};color:${readable(hex)}` } : undefined);
  hide(base + e - 7, base + e);

```

- The `mark` helper already accepts an attribute map (`livePreview.ts:398, 431-437`) —

  luminance split, so a pale yellow highlight stays readable in dark mode (memory:
  `theme-tokens-have-contrast-floors`).
- **Security:** only a validated `#hex` ever reaches a `style` attribute. Arbitrary note
  text is never interpolated.

## Fix 6 — `Ctrl/⌘+Shift+A` for Ask AI

**File:** `src/components/editor/AskBar.tsx` (extend the existing `onGlobalKey`, line 65)

```ts
if ((e.metaKey || e.ctrlKey) && e.shiftKey && e.key.toLowerCase() === "a") {
  e.preventDefault();
  const view = editorView();
  const r = view?.state.selection.main;
  if (view && r && !r.empty) startAskAboutSelection(view.state.sliceDoc(r.from, r.to), r.from, r.to);
  else openAsk();
}
```

**Why here and not in the CM6 keymap:** `editor/createEditorState.ts` cannot import
`state/ai.ts` — that would close the cycle `createEditorState → state/ai → state/editor →
createEditorState`. `AskBar` already owns a document-level keydown listener and already
imports `state/ai`, so this is zero new coupling. It is mounted exactly when a note is open
(`App.tsx:84-86`), which is exactly when the shortcut is meaningful.

**Why `Ctrl+Shift+A`:** `Ctrl+K` is taken by the Ask-bar toggle; `Ctrl+Shift+K` is CM6
`defaultKeymap`'s `deleteLine`; `Ctrl+Shift+A` is unbound in `defaultKeymap`,
`markdownKeymap`, `historyKeymap` and `completionKeymap`. The shortcut is rendered on the
Ask AI menu row so it's discoverable.
